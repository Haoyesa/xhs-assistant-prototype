# 黑猫智记AI · 产品重新定位与架构设计方案

> 版本：v1（草案，待评审）
> 日期：2026-07-28
> 目的：将产品从「小红书自动化发布工具」重新定位为「通用内容创作辅助工具」，并据此调整产品架构、功能模块、品牌与合规边界。

---

## 一、定位变更摘要

| 维度 | 旧定位 | 新定位 |
|---|---|---|
| 产品类型 | 小红书笔记批量发布自动化工具 | 通用内容创作辅助工具（纯编辑能力） |
| 核心能力 | 选品→生成→自动发布（含 CDP/插件真实点击） | 文案优化、排版设计、敏感词检测、封面素材参考 |
| 平台耦合 | 强绑定小红书（千帆、创作者页、xhs-publish-btn） | 平台中立，不接入任何平台接口 |
| 数据流向 | 抓取平台商品/用户数据、驱动浏览器发布 | 全程本地，不抓取、不上传、不发布 |
| 账号模型 | 多账号绑定 + 套餐配额门禁 | 不提供多账号批量管理 |

## 二、新定位核心原则

1. **纯编辑、零发布**：工具只在用户本地完成文案/排版/检测，不连接任何平台发布接口，不实现自动发布。
2. **平台中立**：UI 命名、文案、提示词均不绑定单一平台；功能可服务图文、短视频脚本、电商详情等多场景。
3. **本地优先**：所有编辑操作在用户本机完成，数据不上传厂商服务器，不收集/存储任何平台账号密码。
4. **合规护栏**：内置敏感词/违禁词检测，并在用户协议中明确禁止虚假种草、批量搬运、刷量等违规用途，划清责任边界。

## 四、新架构与模块设计

```
黑猫智记AI（通用内容创作辅助工具）
├─ 桌面外壳 electron/
│   ├─ main.mjs            启动本地服务 + 窗口（保留）
│   ├─ activation.*        激活页（保留）
│   ├─ license.mjs         授权校验（保留）
│   └─ plans.mjs           套餐=编辑能力配额（重写：去掉 accounts/autoSubmit/freqTier）
├─ 本地服务 server.js      HTTP(本机) 仅服务前端，无出站平台请求
│   ├─ AI 文案优化模块      callAI / aiGenerateNote（保留，去平台风格）
│   ├─ 素材库模块          /api/materials（原 products，重命名）
│   ├─ 敏感词检测模块      /api/sensitive/check（新增，本地词库）
│   ├─ 封面参考模块        /api/generator/*（保留作图+图片入库，去发布语义）
│   └─ 设置/历史           /api/settings、/api/history（保留，精简）
├─ 前端 public/
│   ├─ 文案优化 tab
│   ├─ 素材库 tab（原商品/采集）
│   ├─ 封面素材参考 tab（原批量作图）
│   ├─ 敏感词检测 tab（新增）
│   ├─ 创作历史 tab
│   └─ 设置 tab
└─ 授权服务 license-server/（保留，仅机器码，无平台数据）
```

要点：
- **server.js 不再 import** cdp-publisher / qianfan-scraper / electron/gating（自动化控制）；删除 runPump 与所有 /api/cdp、/api/qianfan、/api/ext、/api/accounts、/api/batch/pump 路由。
- **提示词中性化**：`DEFAULT_TITLE_PROMPT`/`CONTENT_PROMPT`/`TOPICS_PROMPT` 去掉「小红书」「种草官」「笔记」等词，改为「通用中文文案助手」，不强制特定平台文风。
- **敏感词检测**：新增本地词库 `data/sensitive-words.txt`（可空，运行时可更新），后端做子串/正则匹配返回命中位置与建议，纯本地、零网络。
- **素材库**：把 `products.json` 语义改为用户自有「素材/选题」，字段保留但文案去商品化；不再有「千帆来源」「itemId 匹配发布页」等逻辑。

## 七、分阶段实施计划（待确认后执行）

- **阶段 0 — 文档与合规（本批已交付）**：定位方案、用户协议、合规核查清单。
- **阶段 1 — 品牌与文案中性化（低风险）**：重命名 UI/提示词/文档中的平台词；改 `appId`；清理逆向文档引用。不改功能结构。
- **阶段 2 — 移除自动化代码（高风险，需确认）**：删除 `extension/`、`cdp-publisher.js`、`qianfan-scraper.js`、`cdp-config.json`；server.js 去发布/爬取/多账号路由；前端去「批量发布/账号/采集」tab。
- **阶段 3 — 新增敏感词检测**：本地词库 + 后端 `/api/sensitive/check` + 前端 tab。
- **阶段 4 — 授权套餐重定义**：`plans.mjs` 改为编辑能力配额；去掉账号/自动提交/频率控制。
- **阶段 5 — 依赖收敛与构建验证**：移除 `puppeteer-core`；`npm run dist` 验证打包；`license-server` 仅机器码。

## 八、风险与回滚

- 阶段 2 为破坏性操作，建议先在 git 打 tag / 分支后再执行，便于回滚。
- 删除 extension/ 后，原「浏览器内自动化」能力整体消失，属预期。
- 敏感词词库为空时检测返回无命中，不阻断使用。
